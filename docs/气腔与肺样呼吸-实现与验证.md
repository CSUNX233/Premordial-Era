# 气腔与肺样呼吸：实现与验证

## 实现范围

当前实现是一个独立的区域气腔生理模块，核心文件为 `src/NativeEpoch.Simulation/CavityPhysiology.cs`。它不定义“肺”器官开关，而是让每个身体区域可以表达一个有限容量、局部开口、可进水、可交换的混合气腔。肺样呼吸只有在多项结构和生理表达同时配合时才会出现。

每个区域最多保存一个均匀混合的气体袋状态，包括腔内氧、淹水比例、有效容积、氧容量和最近一步的通气、泄漏、组织输氧与能耗。这是明确的小型有效容积/表面近似，不是三维体素、气道网格或完整流体求解。

## 从连续遗传到实际作用

气腔依赖两个额外的区域连续遗传字段，取值均为 0..1：

- `CavityFraction`：区域已付费物质中用于形成内腔和腔壁拓扑的投入。有效腔容积同时受局部解析几何体积、发育程度和结构表达限制，不能用同一份物质生成无限容积。
- `CavityAperture`：局部开口尺度。它不代表必然通气；只有对应的局部表面样本对外连通且实际接触空气时，环境空气才能补给腔内氧。

其余能力复用区域组织表达：

- `ExchangeExpression` 决定内交换面效率。
- `BarrierExpression` 决定密封和抗进水能力。
- `ContractileExpression` 与区域激活共同决定主动通气。
- `StructuralExpression` 限制可支撑腔容积和屏障完整性。
- `MatterSourceRegionId`、实际连接状态和 `TransportAvailability` 决定腔内氧能否进入组织运输账本。

因此，大气腔但无开口、有开口但无交换面、交换面与身体运输断开、或者高维护成本导致能量不足，都可能是无用或有害组合。突变不会因为生物上岸而自动获得肺。

## 局部作用和守恒

正式步进入口是 `CavityPhysiology.StepBody`，单区域入口是 `StepRegion`。世界侧需为每个区域构造 `CavityRegionInput`，其中 `CavityApertureContact` 必须来自该区域一个稳定的局部 `BodySurfaceSample`，并使用当前姿态、地形和水面计算其世界位置及介质接触。不能用全身浸没度替代局部开口接触。

模块保持三个氧库之间的守恒通量：

`Environment oxygen ↔ cavity oxygen ↔ regional tissue oxygen`

环境补给通过 `IMutableEnvironmentField.WithdrawOxygen` 实际扣减有限库存。气腔新生或容量增大时只增加空间，不生成氧。水下封闭腔不能从环境补气，只能通过已连接的组织交换消耗原有氧。水下开口会根据屏障完整性进水并排出/泄漏氧。容量缩小时，超出容量的氧先尝试转入已连接组织，剩余部分归还局部环境。生物死亡或被移除时，世界必须调用 `CavityPhysiology.ReleaseAll`。

腔壁维护、交换面维护和主动通气从区域能量库实际支付。低能量会先降低屏障及交换面的有效性，并使主动通气衰减至低效被动扩散水平。即使世界侧错误传入空气暴露，开口样本深度大于水面容差时模块也会拒绝空气补给。

## 可观察数据

`CavitySystemState.Regions` 提供固定上限的区域局部状态。快照或调试界面可直接显示：

- `Oxygen` / `OxygenCapacity`：腔内氧与容量。
- `EffectiveVolume` / `WallMatterCommitted`：有效气体容积与腔壁物质投入近似。
- `OpeningLastStep`、`AirExposureLastStep`、`WaterExposureLastStep`：开口尺度和实际局部介质接触。
- `VentilationLastStep`、`LeakageLastStep`、`FloodedFraction`：空气通气、漏氧/排氧和淹水情况。
- `TissueOxygenLastStep`、`EnergySpentLastStep`、`MaintenanceShortfallLastStep`：组织净输氧和功能代价。

世界快照的总氧和状态指纹需纳入 `CavitySystemState.TotalOxygen` 及上述持久状态，否则世界级守恒和决定性检查不完整。

## 小型诊断结果

诊断入口为 `CavityPhysiologyDiagnostics.Run()`，位于 `src/NativeEpoch.Simulation/CavityPhysiologyDiagnostics.cs`。它直接调用正式模块 API，不运行长时间生态模拟。

| 对照 | 结果 |
|---|---:|
| 局部开口接触空气时的补给 | 0.0352388708 |
| 封闭开口后的腔氧变化 | 0 |
| 水下封闭腔消耗 | 0.1021840360 |
| 水下封闭腔的环境补给 | 0 |
| 断开运输后的组织输氧 | 0 |
| 有能量的主动通气补给 | 0.0352388708 |
| 无能量时的被动通气补给 | 0.0139140059 |
| 容量缩小时归还环境的氧 | 0.0850922296 |
| 死亡释放的腔氧 | 0.0825895166 |
| 最大氧账本守恒误差 | 1.42e-14 |

诊断总结果为 `PASS`；`NativeEpoch.Simulation` 构建为 0 警告、0 错误。

## 性能上限

- 气腔状态数与已发育身体区域数一致，受 `GenomeValidator.MaximumRegions = 32` 硬上限约束。
- 每区域每步仅计算一个均匀气库、一个开口接触和一条局部组织交换通量，不随气腔体积增加求解单元。
- `StepBody` 主计算量为 O(R)，其中 R 不超过 32。重复区域输入检查为 O(R²)，但同样受 32 的固定上限限制，不会按世界网格或气体体积扩张。
- 模块不为每个生物创建摄像机、刚体、体素或流体网格。
- 稳定步进中不使用 LINQ 汇总，不创建每区域临时集合；参数验证在 `StepBody` 层只做一次，每区域的组织氧变化合并为一次账本写入。
- 区域状态只在首次出现时插入有序容器；之后每步就地更新。表面积近似使用 `Math.Cbrt` 而不是通用幂运算。

上述热路径优化后，所有小型诊断指标与优化前逐项一致，守恒误差仍为 1.42e-14。

## 证据边界

上述结果证明独立气腔模块的局部因果和氧账本成立，但不等于气腔已在 `SimulationWorld` 中完整集成。世界集成仍需要：遗传验证/指纹/突变与发育映射，每个生物的 `CavitySystemState` 生命周期，局部开口世界接触，世界步进调用，死亡释放，总氧/指纹/快照统计以及 UI 可观察展示。

独立模块通过也不证明自然选择已产生肺样适应。这需要在世界完成集成后，用同环境的祖先/后代/功能失活对照，检查成熟、生存和成熟后代数。只有外观变化、单次通气成功或个体上岸，都不足以宣布自然适应已被证明。

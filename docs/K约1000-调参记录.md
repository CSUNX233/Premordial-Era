# 默认环境承载目标约 1000

用户要求把生态承载目标调到约 1000 只。本轮只校准默认环境资源参数，不把 `MaxPopulation` 改成 1000，不增加按人口直接死亡或强制补种。

当前状态：默认资源预设校准完成，已构建，等待用户重新运行 Godot 检查。未 Git。

增加 `SimulationConfig.InitialMineralScale`，按同一比例缩放初始矿物分布，保留局部竞争、摄取费用、残骸和代谢废物循环。比较后选择 **1.0**：原矿物浓度在新空间竞争规则下的后期表现已经接近 1000，进一步削减反而低于目标。空间大小、正常生命成本和突变规则保持原设置。

新增 `ResourceBudgetReferenceAncestors=24`，由 Godot 默认世界预设启用。初始祖先的结构与储备物质从同一总预算中分配；300 生物模式比 24 模式多需要的 483 物质，按比例从初始环境矿物中支取。该分配只发生在初始化，不根据运行时人口调节资源或杀生。默认 24 生物的初始分布不变。

固定默认种子 20260908 下，预设总物质约 **3167.946**：24 生物启动时环境矿物 3125.946、祖先物质 42；300 生物启动时环境矿物 2642.946、祖先物质 525。两者总预算一致，但初始密度、能量及空间分布不同，不声称生态轨迹相同。

## 校准结果

以下均为默认 24 生物、种子 20260908，不使用环境笔刷，不关闭死亡或突变；每步仍为 0.1 秒。表中时间为模拟秒。

| 时间 | 原矿物比例 1.0（采用） | 比例 0.9 | 比例 0.65 |
|---:|---:|---:|---:|
| 300 | 295 | 256 | 187 |
| 600 | 654 | 533 | 288 |
| 900 | 662 | 620 | 287 |
| 1200 | 673 | 676 | 364 |
| 1500 | 785 | 830 | 390 |
| 1800 | 932 | 928 | 435 |
| 2100 | 929 | 879 | 474 |
| 2400 | 975 | 917 | 395 |

采用配置末三个采样点为 **929～975 只，均值约 945**，作为“约 1000 只”的当前参考。最后两个 300 秒区间的出生/死亡分别为 1070/1073、1147/1101；有持续出生和死亡，并非触及 5000 安全上限。2400 秒最终物质误差 3.183e-12。

矿物比例 1.2 的补充对照到 1200 秒为 1032 只；发现原比例已满足目标后停止该对照，没有伪称完成 2400 秒。0.9 在另一种子 20260909 的末三个采样点为 918/850/817，更偏低；该对照未作为最终预设的多种子验证。

## 初验及使用

`--verify --seed 20260908 --steps 600 --ancestors 4` 通过，指纹 71B41FF8D4659727；新增 `shared_founder_matter_budget=True`，检查 24/300 生物的初始化总账一致且环境矿物差恰好等于额外祖先物质。Godot Debug 构建 0 警告、0 错误，实际 .NET Godot 无窗口启动 60 帧后正常退出，无报错。

停止旧游戏后重新 F5，或重新载入默认世界，才能应用新的初始化预算。状态栏显示约 1000 只的资源承载目标。运行中新增资源、改变环境或体型演化都可能使承载区间移动；不会到第 1000 只时硬停繁殖。

重跑采用配置的生态轨迹：`dotnet run --project src/NativeEpoch.Headless/NativeEpoch.Headless.csproj -c Release -- --diagnose-ecology --seed 20260908 --ancestors 24 --steps 24000 --report-every 3000`。该默认 24 数量的物质预算与 Godot 预设一致；额外祖先模式的预算通过专门初始化断言检查。

K 是当前环境及生物能力下的承载区间，不能保证每一时刻恰好 1000。不同谱系、空间利用和用户环境干预可能改变实际人口。需要将程序安全上限、初期增长峰值、后期承载区间分别解释。

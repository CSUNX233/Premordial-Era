# 空间竞争与个体互动

本轮由用户授权补齐空间占用、拥挤反馈、局部资源竞争，并增加个体间的互动。当前状态：实现与主 agent 初验完成，停止等待用户在 Godot 中检查；未 Git。

## 要解决的问题

世界边界和有限物质库存已经存在，但原有邻居推开半径固定为 2.8，与身体尺寸无关；出生只检查是否有水，没有检查身体能否放下。`ContactPressure` 未被赋值，控制器实际收不到拥挤信号。物质摄取按列表顺序进行，先执行的个体可能长期优先取得稀缺资源。

## 本轮边界

- 体型、位置和深度共同决定低成本占用近似；使用空间索引处理局部接触。
- 新生身体需要合法且空余的位置。位置不足时延后繁殖，亲代保留尚未投入的物质和能量。
- 接触信号进入行为。个体可以避让、争夺觅食位置或付费挤开对方，低能量个体不会获得免费主动推力。
- 局部资源按照有限库存竞争，实际摄取仍需支付同化成本。竞争不以全世界总人口直接乘死亡率实现。
- 观察器显示压力和互动信息，方便区分正常探索、争夺与退让。没有新增捕食、伤害战斗、视觉、肺或腿。

## 初验标准

检查体型与深度对占用的影响、出生失败的账本、接触响应、稀缺资源的公平竞争，以及守恒、确定性、探索与低能休息回归。只做针对性诊断和一个短程代表性负载检查；完成后交给用户在 Godot 观察。

## 实现采用的近似

占用使用水平外廓半径与实际区域垂直厚度组成的简化形状，不逐三角面碰撞。它会保守估计长条、弯曲和分叉身体的空隙，不等于精确皮肤接触，也没有证实误差恰好为 10%。空间索引服务于模拟，和相机可见性、渲染 LOD 无关。

本轮食物公平分配以身体中心所在的资源格为单位，按照区域暴露面、库存空位及能量预算估计需求，再按比例预留矿物和有机物。实际摄取仍逐区域支付同化能量；没有用完的份额按原矿物/有机物比例退回原格，不能随移动带到另一个格。本轮没有把资源场升级为完整三维体素，也不把食物分配的公平性扩张解释为氧交换、出生顺序或整个模拟完全无遍历顺序影响。

每步最多两次局部重叠修正，极端堆叠仍可能有残余穿透或位置抖动。4% 的薄接触范围使身体分开后仍能感知贴近顶推；主动争位的力预算按接触权重分配，不能把一次付费复制给每个邻居。近岸的身体部分出水仍是简化处理，不是精确的三维海底刚体接触。主 agent 修复了碰撞修正跨到浅水后深度未重新约束的问题。

个体检查器增加接触压力、接触邻居、互动状态、对方 ID、实际争位强度和食物需求满足情况；无需求时直接显示“无摄取需求”。顶部只增加拥挤数量，保持原统计行数。

## 用户在 Godot 中检查

停止旧的运行实例后，用 .NET 编辑器重新按 F5。先观察默认 24 生物的正常游动和繁殖，再拉近有接触的个体，点击选择，在检查器查看“接触压力”“互动”“对方 ID”和“本步食物需求满足”。无接触个体显示“无接触互动”是正常现象，不应让全世界的生物一直争执。

空间和食物竞争随着局部密度上升而增加；低密度初期不保证频繁互动。可以使用已有 300 生物观察模式提高相遇机会，但它不是 K 稳定性试验。留意生物靠近后是否分开、是否恢复探索，以及近景是否存在明显穿透或跳动。当前约 2000 活体的帧尾延迟问题仍沿用上一轮已知限制，本轮短测不能替代完整性能验收。

## 承载量的解释

`MaxPopulation` 是程序安全上限，不是环境承载量 K。资源供给、循环、可居住空间、体型、维护和亲代投资共同限制种群；改变环境和遗传体型也可能改变承载区间。本轮机制测试不能单独证明长期人口稳定，更不能将短期出生增加或程序触顶写成 K 验证通过。

上一轮两种子 1200 秒仍有持续出生和死亡，证明了当时配置下的延续能力，没有证明人口平台。本轮如未完成长期收敛对照，应继续明确保留该验收边界。

## 2026-09-09 实际初验结果

- `--diagnose-competition`：COMPETITION PASS。幼体/完整身体外廓半径 0.37690 / 0.97803；同 XY 不同深度可错开。成熟个体接触试验结束时距离/半径和为 1.00052；首帧之后 19 帧出现争位，最大接触压力 0.03921，累计主动互动耗能 0.0018933。低能对照互动耗能为 0。
- 同格等需求分配差为 0，反转请求顺序后的分配差为 0；预留后原格返还的物质误差为 0。该测试验证分配器，不表示所有局部生理过程都严格无顺序影响。
- 密集出生诊断：62 次出生，111 次因空间不足延后，失败分支母体能量和底物损失为 0，物质误差 6.821e-13。这个场景明确使用 8×8 小世界、32 祖先、加速发育、较高但有限光通量及一次记账矿物笔刷，目的是排除饥饿而触发空间限制；不是默认生态，也不是自然 K 证据。
- 默认生态：种子 20260908、24 祖先、不调整环境，300 秒后存活 295，出生 312、死亡 41，最高第 4 代；185 个后代达到成熟，其中 114 个基因与祖先不同。物质误差 2.728e-12。该短程确认正常生长/出生/死亡未被空间约束卡死，不宣称长期稳定或适应优势。
- `--verify --seed 20260908 --steps 600 --ancestors 4`：VERIFY PASS，重复指纹 71B41FF8D4659727，深度合法、守恒、付费生长和代谢等检查通过；此短样本只有 4 次出生，没有自然突变出生，不能以它单独证明变异率。
- `--diagnose-movement`：MOVEMENT PASS。健康个体 120 秒净位移 60.649，路径 60.650，31.01 体长，访问 18 个资源格；低能量 10 秒位移和探索强度均为 0。
- 主 agent 最终 Debug Godot 工程构建：0 警告、0 错误；实际 Godot .NET 无窗口启动 60 帧后正常退出，无报错。此项只验证启动，视觉体验留给用户。

核心性能短测：1000 祖先预热 8 秒，再模拟 30 秒，最终 1973 活体；每模拟步平均 51.554 ms、P95 75.761 ms、最大 81.450 ms。其中环境分配平均 1.934 ms、接触邻域 1.340 ms、区域交换 15.543 ms、力学 8.813 ms、生长/占用/繁殖段 17.205 ms。物质误差 3.638e-12，数值有限。该计时包含整段种群增长，是无渲染的核心测试，不是游戏帧率；不能据此宣称约 2000 活体不卡顿，也不能与上一轮 Godot 帧时间直接作前后比例比较。

重复功能诊断：`dotnet run --project src/NativeEpoch.Headless/NativeEpoch.Headless.csproj -c Release -- --diagnose-competition`。其余两项分别使用 `--verify` 和 `--diagnose-movement`。本轮结束，不继续增加机制或长期实验。
